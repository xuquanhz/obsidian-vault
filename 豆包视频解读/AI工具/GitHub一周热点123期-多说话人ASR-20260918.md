# GitHub 一周热点 123 期：最强多说话人 ASR、并行 Agent 工作台等 5 个项目

> **视频主张**：本期盘点 5 个 GitHub 热门项目，头牌是 OpenMOSS 的 **MOSS-Transcribe-Diarize**——把"语音转录 + 说话人分离 + 时间戳"统一建模成一个 0.9B 自回归生成模型，一个模型一次出齐"说什么、谁在说、什么时候"。
> **已核实**：5 个项目仓库全部真实存在；注意 AI 转写稿把项目名念错了——是 **MOSS** 不是"Open Mouse"，是 **Orca** 不是"Oracle"。

**一句话结论**：本期最有实用价值的是 MOSS-Transcribe-Diarize（会议/播客/访谈转写场景直接可用），但**本地部署需要 NVIDIA GPU**，我本机（AMD 无独显、C 盘不足 5G）跑不动，用在线 Playground 或继续用腾讯会议 AI 纪要更现实。

## 项目 1 详解：MOSS-Transcribe-Diarize（本期主角）

- **解决什么**：传统做法 ASR 一套、说话人分离一套、再对齐，流程长且易错位。它把三者统一为自回归生成：输入原始音频，直接输出 `[开始秒][S01]文本[结束秒]` 格式的带说话人标签转写。
- **成绩（官方已证实）**：
 - 2026-07-14 获 **Interspeech 2026 第二届 MLC-SLM Challenge 第一名**（14 种语言）
 - 官方称 Open ASR Leaderboard 开源模型第一（细节见仓库 Evaluation 表）
 - Apache-2.0 开源，2026-07-09 开放权重，另有更强的 **Pro 版**（仅在线 Playground）
- **工程与部署**：推荐 **SGLang Omni 或 vLLM** 部署（官方基准为单卡 H100）；FunASR ≥1.4.12 提供生产级接入（vLLM/SGLang/Transformers 三条路径），配套 Web 字幕工作流（中英双语）与热词自定义。
- **典型场景**：会议纪要、访谈、播客切片、长视频拆解——正好是"谁说了什么"比"说了什么"更重要的场景。

## 本机适配性判断（能不能在我机器上跑）

| 条件 | 现实情况 |
|:--|:--|
| GPU | 官方基准按 **NVIDIA H100** 给出；vLLM/SGLang 均要求 CUDA。**本机 AMD 无 N 卡，跑不了** |
| 磁盘 | 模型权重数 GB 起，C 盘仅剩约 4.3G，不够 |
| 结论 | ❌ 本地部署不可行；✅ 可用官方在线 Playground 体验，或经 FunASR 生态调远端服务 |
| 替代 | 会议转写需求继续用腾讯会议 AI 智能纪要（现有工作流）；多说话人分离强需求再考虑租 GPU |
