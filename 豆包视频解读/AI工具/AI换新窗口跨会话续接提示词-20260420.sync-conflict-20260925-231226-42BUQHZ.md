# AI换新窗口怕它全忘？跨会话上下文续接提示词大全

## 问题场景

AI 对话窗口有上下文长度限制，聊久了要开新窗口，但之前的讨论、决策、进度都会丢失——AI"失忆"了。**在关掉旧窗口之前，先让 AI 自己生成一份"交接摘要"**，贴到新窗口就能无缝续接。

---

## ⭐ 精简版：交接摘要（日常首选）

最适合日常快速续接，读一遍不到 1 分钟。

```
请建立一份我可以贴到新聊天中的交接摘要。请包含：
1. 我们想完成什么
2. 目前已做出的关键决定
3. 有哪些重要信息是你如果用猜的可能会猜错的
4. 下一步该做什么

请保持精简，让人能在一分钟内读完。
```

---

## 📦 完整版：项目交接包（复杂项目用）

包含 16 个模块，适合开发项目、长期任务。

```
我准备开一个新聊天继续这个项目。请你不要依赖"用户记忆"，而是仅基于我们当前这个聊天记录，把这个项目相关的所有信息完整整理成一份"项目交接包"。

目标：我要把你输出的内容直接复制到一个新聊天里，让新的 AI 在没有旧聊天上下文的情况下，也能尽可能完整理解这个项目，并无缝继续工作。

严格要求：
- 只基于这段聊天里已经出现过的信息整理，不要编造，不要脑补
- 所有不确定的内容必须标注：【已确认】/【高概率推断】/【待确认】
- 不要省略细节，不要只给简略版总结
- 如果内容太长，请分多条消息连续输出，标明 PART 1/N, PART 2/N …
- 尽量保留原始措辞中的关键信息、数字、约束、决策理由、比较结论、待办事项

请按下面结构输出：

1. 项目身份（项目名称 / 一句话定义 / 要解决什么问题 / 当前所处阶段）
2. 项目目标与成功标准（总目标 / 子目标 / KPI / 明确不做的范围）
3. 背景与上下文（为什么开始做 / 业务场景 / 用户场景 / 前提假设）
4. 目前已经确定的事实（按主题归类，尽量完整列出）
5. 关键决策记录（决策内容 + 为什么这么定 + 被否决的替代方案）
6. 所有需求汇总（功能需求 / 非功能需求 / UIUX 偏好 / 技术要求等）
7. 技术实现信息（技术栈 / 架构 / 数据结构 / 依赖项 / 已发现的问题）
8. 已完成内容（已完成任务 / 已产出成果 / 已验证 / 已否决方向）
9. 未完成内容 / 待办事项（按 P0/P1/P2 优先级分组，写明下一步）
10. 所有悬而未决的问题
11. 我在这个项目中的偏好与要求（风格 / 输出格式 / 优先级 / 速度 vs 质量偏好）
12. 重要原话或高价值指令（保留原意）
13. 项目时间线
14. 风险与坑点（已踩过的坑 / 容易误解的点 / 新聊天必知的注意事项）
15. 给"新聊天"的启动说明（项目是什么 / 当前进度 / 下一步 / 应遵守的规则）
16. 极简版摘要（10~20 条 bullets 超浓缩版）

补充要求：
- 如果发现聊天里有互相矛盾的信息，请单独列出"冲突点"
- 除了完整版本外，再额外给一版适合粘贴到新聊天首条消息里的压缩版
```

## 🧟 对话复活包（简洁万能版）

适合任何类型的对话，结构轻量但信息完整。

```
请根据我们刚才的对话，生成一份对话复活包：

【主题/项目名称】：
【日期】：
【当前核心目的】：（一句话）
【当前阶段或进度】：
【本次确认的结论和决策】：（不超过 5 条）
【当前卡点或待解决问题】：
【下一步行动】：
【本次对自己的承诺】：（可以被检查的行为）
【给新对话框的指令】：
你已读完以上复活包。在开始任何工作之前，先问我：
1. 距离上次跟进，有没有新的想法或观察？
2. 这次最想解决的一个问题是什么？
收到回答后评估置信度，低于 95% 继续追问，达到 95% 说好，可以开始进入工作。
```

## 💻 编程/Agent 专用：结构化续接

面向开发场景，聚焦可执行性，不记流水账。

```
你正在接手一个已经进行过多轮的 AI 对话。请按以下上下文恢复任务状态；如果当前文件或可验证证据与这里冲突，以当前证据为准。

【工作目录】
...

【用户目标】
...

【必须遵守的要求】
- [已验证] ...
- [推断] ...
- [未验证] ...

【已完成】
...

【未完成 / 待验证】
...

【关键文件 / 命令 / 产物】
...

【不要重复 / 不要做】
...

【下一步】
1. ...
2. ...
3. ...
```

## 🧠 Skill 提炼版：沉淀长期协作模式

不记短期事件，只提取长期稳定模式，适合固定搭档式协作用户。

```
请从这段对话中提取以下长期稳定信息：

1. 用户长期稳定的思维和决策模式
2. 用户希望 AI 如何协作
3. 用户纠正过 AI 的关键时刻
4. 三个月后仍可能成立的事实底座
5. 没有证据支撑、需要单独验证的推断

要求：
- 只提取模式，不记录短期事件
- 每条结论必须附用户原话证据
- 不知道就写"本窗口无此信息"
- 不确定的信息放入待验证区，不要混入正文
```

## 🎯 Gemini 专用衔接提示词

针对 Gemini 长时间对话记忆混乱问题。

```
为防止长时间聊天出现记忆遗失混乱，请生成一段能有效衔接的 Prompt。
要求：
1. 我发送该内容到新对话窗口后，模型可立即恢复过往对话的关键信息，无缝承接上一轮的分析方向与结论，避免重复沟通。
2. 需明确我们的分析节点与核心结论，实现无断点续聊。
```

## 📊 场景速查

| 场景 | 推荐模板 |
|------|----------|
| 日常问答快速续接 | 精简版「交接摘要」或「对话复活包」 |
| 复杂项目管理/开发 | 完整版「项目交接包」 |
| 编程/Agent 长任务 | 结构化「AI 对话续接」 |
| 沉淀长期协作模式 | Skill 提炼版 |
| Gemini 用户 | Gemini 专用衔接提示词 |

---

## 🔑 核心原则

1. **在关旧窗口之前生成** — 上下文还在，AI 能完整回顾
2. **新窗口第一条消息就贴** — 让 AI 从正确上下文开始，而不是从零猜
3. **根据自己的场景选模板** — 日常问答用精简版就够了，别用 16 模块的大炮打蚊子
