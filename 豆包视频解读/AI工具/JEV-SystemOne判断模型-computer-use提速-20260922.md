# JEV：不写字只判断的 System One 模型，computer-use 被它提速了

> **视频主张**：用 jev-voice 做 computer-use，速度"是真的快"——以前云端模型截图后要思考 5 秒，现在接近实时；作者预判"解放双手"的时代不远，连关电脑都是一句话的事。
>
> **核实结论**：JEV 真实存在——TypeSafe AI（前 OpenAI 研究员 Diogo Almeida 创办）2026 年 9 月中旬发布，定位"System One Model"：**不生成文本，只做封闭选项判断**。视频演示与官方口径一致，但"快"的倍数存在宣传水分（见对照表）。

**一句话结论**：JEV 不是又一个聊天大模型，而是给 Agent 执行链配的"闪电判断层"——它把"下一步点哪、走哪个分支"这类封闭判断从大模型手里剥离，用一次并行打分替代逐 Token 生成，这是 computer-use 提速的原理。

## JEV 是什么（官方/媒体口径核实）

- **出身**：TypeSafe AI 出品，创始人 Diogo Almeida 为前 OpenAI 研究员，2026-09-16/17 发布；"Jev"取名自经济学家杰文斯（Jevons Paradox：判断便宜到忽略不计，需求反而暴涨）
- **机制**：与 LLM 逐 Token 自回归生成相反，JEV 对预定义的封闭选项集合**一次并行打分**、直接输出"选项+概率+置信度"。官方称结构化输出/工具调用错误率 0%，对照主流大模型 0.x%~45.5%（TypeSafe 自测口径）
- **三个判断原语**：Choice（从候选项选一个）/ Noul（命题真伪概率）/ Score（量表打分），可共享上下文一次并行完成多判断
- **性能与价格**（2026-09-19 官方文档口径，时效性强）：延迟约 100ms；输入 $0.042/百万 Token，输出不计费；64k 上下文；10 万次工单判断约 $1.26
- **社区玩法**：jev-ultrafast（Browser Use + JEV，苏黎世→伦敦航班查询全程 7.1 秒，浏览器调用从 1000+ 次砍到 100 出头）；jev-desktop（macOS 无障碍树 computer-use，普通步骤置信度门槛 0.70、破坏性操作 0.90）；jev-voice-browser（语音驱动 Chromium）；Jev Codex Router（先判难度再路由模型）

## 串起来的框架：Agent 执行链的"双系统"分工

```
 人/主模型（System 2，慢思考）：理解目标 → 拆解规划 → 生成内容 → 最终校验
            ↓ 下发候选动作
 JEV（System 1，快判断）：界面状态 + 候选控件 → 一次打分 → 选项+置信度
            ↓ 执行代码按置信度分级处理
 高置信 → 自动执行 / 中置信 → 二次确认 / 低置信 → 交回主模型或人工
```

判断它适不适合你的任务，三问：**结果能否预先枚举？能否用标注数据验证？是否高频重复？** 三全是典型场景（工单路由、内容分类、RAG 片段初筛、Agent 下一步动作），三否就老老实实交给生成式模型。

## 落地对接：本机与园区场景

| 维度 | 判断 |
|---|---|
| 本机算力 | ✅ 无压力——JEV 走 API 调用，不吃本地 GPU（AMD 无独显也不碍事） |
| 网络 | ⚠️ 需访问 TypeSafe API，代理链下先测连通性；数据出境，别碰涉密/客户敏感信息 |
| 磁盘 | ✅ API 模式几乎不占空间 |
| 园区场景候选 | ① 工单/报修分类路由（Choice）；② 合同/发票要素预筛（Noul）；③ 客商咨询情绪分级（Score）——都是"高频+封闭选项+可验证"的典型形态 |
| 接入路径 | 官方 waitlist → `npx skills add typesafe-ai/skills`（支持 Codex）或 jev-mcp；Vercel/OpenRouter 已可调用，测试成本极低（有测试者玩几小时花费不到 1 美元） |
